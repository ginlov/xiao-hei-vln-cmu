The proposal

Stop naming objects. Ask for the phrase.

Instead of detecting 110 fixed classes and hoping the instruction's word is among them, hand the VLM the referring expression verbatim and ask where it is.

Today

YOLO-World, 110 classes
→ label committed at detect time
→ fuse by exact label match
→ query by synonym family
→ ceiling 67%

Proposed

“the tea table with the
elephant figurine on it”
→ VLM returns a box
→ lidar lifts it to 3D
→ no vocabulary at all

One move removes three separate problems we have been fighting: the vocabulary limit, synonym splitting (side table / coffee table / dining table), and duplicate nodes. The compound phrase is handled natively — no need to find tables first and check each for an elephant.

Architecture

The VLM proposes. Geometry validates and executes.

01 · VLM Parse Instruction → ordered constraints with roles: goto, stop_at, pass_by, between, avoid, landmark. One call per question.
02 · VLM Ground “Is this phrase visible? Which face, which box?” Also binds any not-yet-located constraint it happens to see.
03 · Geometry Lift & check Box → SAM → mask → lidar. Reject if no returns on that ray — the only defence against a confident hallucination.
04 · Geometry Enforce Keep-out zones, “between A and B”, has-the-robot-arrived, where-we-have-been. All deterministic.

Memory is a table, not a model. Three to six bindings per question — constraint, position, satisfied-or-not. Small enough to sit in every prompt, exact because it never round-trips through language.

Progress is judged geometrically, never by the VLM: did the trajectory come within 1 m of the bound position? That is the same test the grader applies.

The case that decides it

Retrieval localises 1 of 5 here, and stays at 1 of 5 after the full tour. But a person looking at the panorama can see which table the elephant sits on. No geometric feature separates five tables — this is where a VLM is not merely better but necessary.

The last row matters most. A miss costs one question; a confident wrong answer sends the robot elsewhere and corrupts the ordering of everything after it. NOT_VISIBLE must be easy to say.

Decision rule

≥ 67% VLM grounding becomes the primary path; the detector demotes to fallback.
50 – 67% Keep YOLO, but push the question's own words through set_classes; use the VLM only for compositional disambiguation.
< 50% Drop VLM grounding. Pursue narrow vocabulary alone.

Feasibility

The numbers say this is buildable

Gemini returns boxes natively

box_2d as [ymin,xmin,ymax,xmax] normalised to [0,1000], plus a segmentation mask. A trained capability, not coaxed out of general multimodality.

Pixel precision is not the risk

At 5.33 px/deg, staying under 0.58 m of lateral error allows ±86 px at 2 m and ±35 px at 5 m. Named objects sit mostly 2–6 m out.

Depth is the risk

Twenty pixels past the silhouette and the ray hits the wall behind — error along the ray is unbounded. Mitigated by feeding the box to SAM and reusing _dominant_depth_cluster.

Latency is not a problem because we do not need per-frame understanding: one call per decision point, 10–30 per question against a 10-minute budget. Online APIs are explicitly allowed — but the token ships with the submission, so it must be revocable and quota-capped.

A fallback is mandatory, not optional. The API sits on the critical path on someone else's machine; a timeout must degrade to geometry, because instruction following is scored on the trajectory the robot actually drove and a crash scores zero.
